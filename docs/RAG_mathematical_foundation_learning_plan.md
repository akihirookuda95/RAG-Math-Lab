# RAG技術の数学的基礎理解：学習概要書

## 1. 学習の目的

### 1.1 なぜこの学習をするのか

**現在の課題**
- ハイブリッド検索やリランカーを実装し、精度が上がることは経験的に知っている
- しかし「なぜ効くのか」を数学的・統計的に深く理解できていない
- 他社の事例や経験則で判断することが多く、根源的な理解がないまま仕事が先に進む
- この状態に「もやもや」を感じている

**目指す状態**
- 数式レベルで「なぜその手法が効くのか」を理解できる
- データと理論の両面から技術選択の根拠を説明できる
- 新しい手法（Agentic RAG、Graph RAGなど）が出ても、原理から効果を予測できる
- コスト・精度・レイテンシのトレードオフを定量的に判断できる

**なぜプライベートで学ぶのか**
- 仕事では「動く」「効く」が分かれば次に進む必要がある
- 基礎をとことん深堀りする時間は業務時間内では取りにくい
- しかし基礎的な数学的理解は**複利で効く**投資である
- 物理・機械工学のバックグラウンドを持つ自分としては、第一原理からの理解がないと腑に落ちない

**最終的なゴール**
- 仕事でのRAG最適化（コスト・精度・レイテンシ）において、理論的裏付けを持って意思決定できる
- 2027年の転職（Stockmark、LayerX）で、技術的深さを示せる
- 新しいRAG手法が登場しても、数学的原理から理解し評価できる

---

## 2. 理解の3つの階層

### 階層1: 数学的基礎（最重要・最優先）

全ての土台となる数学。一度理解すれば、どんな新しいRAG手法も同じ数学で理解できる。

#### 1.1 線形代数（ベクトル検索の本質）

**理解すべきこと**
- ベクトル空間の幾何学：なぜ高次元空間で「近い」が意味を持つのか
- 内積の意味：$v \cdot u = ||v|| \cdot ||u|| \cdot \cos\theta$ の幾何学的解釈
- 射影：クエリベクトルをドキュメント空間に射影する意味
- 次元の呪い：なぜ高次元で距離が無意味になるか（でも内積は有効）

**なぜ複利で効くか**
- Graph RAGのembedding → 同じベクトル空間の話
- Multi-vectorの最適化 → 線形代数の最適化問題
- 新しいembedding手法が出ても、数学的本質は同じ

**学習リソース**
- Gilbert Strang『線形代数入門』第1-3章（ベクトル、内積、射影）
- 手を動かす：NumPyで実際に計算

**確認基準**
「コサイン類似度がなぜ角度を測るのか」を数式で説明できるか

---

#### 1.2 情報理論（検索とランキングの本質）

**理解すべきこと**
- エントロピー：情報量の定量化
- 相互情報量：クエリとドキュメントの「関連性」の数学的定義
- KLダイバージェンス：2つの分布の「違い」の測り方
- 情報ボトルネック：なぜ二段階検索（検索 + リランカー）が必要か

**なぜ複利で効くか**
- BM25のIDFは情報理論から来ている
- Rerankerは情報ボトルネックの解消
- LLMの次トークン予測も情報理論
- どんな検索手法も「クエリとドキュメントの相互情報量最大化」という同じ問題

**学習リソース**
- David MacKay『Information Theory, Inference, and Learning Algorithms』第2章

**確認基準**
「BM25のIDFがなぜlog(N/df)なのか」を情報理論で説明できるか

---

#### 1.3 確率・統計（評価と最適化の本質）

**理解すべきこと**
- ベイズ推論：事前分布と事後分布、なぜベイズが強いか
- 仮説検定：精度改善が「本当に改善」なのか統計的に判断
- 信頼区間：「精度85%」の±はどれくらいか
- 多重比較問題：10個の手法を試したとき、偶然良い結果が出る確率

**なぜ複利で効くか**
- A/Bテスト、評価フレームワーク設計の基礎
- 「この改善は偶然か、本質的か」を判断できる
- マルチクエリの最適化 → 確率的な問題

**学習リソース**
- 『統計学入門』（東京大学出版会）の基礎部分

**確認基準**
「精度が3%向上したが、これは統計的に有意か」を計算できるか

### 階層2: RAGの数学的構造（応用）

数学的基礎の上に、RAG特有の理論を積む。

#### 2.1 BM25の数学的導出

**理解すべきこと**
- TF-IDFからBM25への進化の数学的根拠
- なぜ $k_1$ と $b$ というパラメータが存在するか
- ドキュメント長の正規化の意味

**数式の理解**
```
BM25(q,d) = Σ IDF(t) × [f(t,d) × (k₁ + 1)] / [f(t,d) + k₁ × (1 - b + b × |d|/avgdl)]

この式の各項が何を表すか、微分したらどうなるか、極限を取ったらどうなるか
```

**学習リソース**
- 論文："The Probabilistic Relevance Framework: BM25 and Beyond"
- 手を動かす：BM25を自分で実装し、パラメータを変えて挙動を観察

**確認基準**
「なぜ文書長で正規化する必要があるか」を数式で説明できるか

---

#### 2.2 Embedding空間の幾何学

**理解すべきこと**
- Word2Vec/GloVeからBERTへの進化の数学的本質
- なぜBERTは「文脈」を捉えられるのか（Self-Attentionの数式）
- Bi-EncoderとCross-Encoderの情報理論的な違い

**数式の理解**
```
Attention(Q,K,V) = softmax(QK^T / √d_k)V

なぜ √d_k で割るのか、softmaxの意味、Query/Key/Valueの役割を幾何学的に理解
```

**学習リソース**
- 論文："Attention Is All You Need"（Transformer原論文）
- 論文："Sentence-BERT"（Bi-Encoderの理論）

**確認基準**
「Cross-EncoderがなぜBi-Encoderより強いか」を数式で説明できるか

---

#### 2.3 ハイブリッド検索の理論的基盤

**理解すべきこと**
- アンサンブル学習の数学的根拠（なぜ組み合わせると良くなるか）
- 独立性の重要性（BM25とベクトルが捉える情報の独立性）
- 正規化の数学（Min-Max、Z-score、RRFの違い）

**数式の理解**
```
2つの独立した分類器の誤り率:
P(both wrong) = P(A wrong) × P(B wrong)

これがハイブリッドが効く数学的根拠
```

**学習リソース**
- 統計的学習の基礎（アンサンブル学習の章）

**確認基準**
「なぜ独立した手法を組み合わせると精度が上がるか」を数式で説明できるか

---

### 階層3: 最適化の理論（メタレベル）

#### 3.1 トレードオフの数学的定式化

**理解すべきこと**
- パレート最適：コスト・精度・レイテンシの同時最適化は不可能
- 制約付き最適化：「レイテンシ < 200ms」の制約下で精度を最大化
- 多目的最適化：どの解が「最適」か

**数式の理解**
```
最大化: f(x) = accuracy(x)
制約: g(x) = cost(x) ≤ budget
     h(x) = latency(x) ≤ 200ms

ラグランジュ乗数法で解く
```

**学習リソース**
- 最適化理論の入門書（制約付き最適化の章）

**確認基準**
「リランカー導入の最適判断」を最適化問題として定式化できるか

---

#### 3.2 評価指標の統計的性質

**理解すべきこと**
- Recall、Precision、F1の数学的関係
- なぜNDCGが優れているか（順位の重み付けの数学）
- Claim-level Faithfulnessの統計的解釈

**学習リソース**
- 情報検索の教科書（評価指標の章）

**確認基準**
「この評価指標を選んだ理由」を数学的に説明できるか

## 4. 学習後にできるようになること

### 4.1 技術的理解の深化

**現在（もやもや状態）**
- 「ハイブリッド検索を使うと精度が上がる」
- 「リランカーを入れたら精度が向上した」
- 「なぜかは分からないが、他社もやっているから導入」

**学習後（腑に落ちた状態）**
- 「BM25は語彙的一致（IDF理論）を、ベクトル検索は意味的類似度（コサイン類似度）を捉える。これらは数学的に独立した情報であり、情報理論的にはアンサンブルによってエラー率を削減できる」
- 「Cross-EncoderのAttentionメカニズムは、クエリとドキュメントのToken-levelの相互作用を学習する。Bi-Encoderは独立に埋め込むため、この文脈的関連性を捉えられない。これが情報ボトルネックであり、リランカーで解消できる」
- 「統計的に有意な精度向上（p<0.05）を確認した上で、コスト増加とのトレードオフを制約付き最適化問題として定式化し、導入判断を行った」

---

### 4.2 新しい手法への対応力

**Agentic RAGが出たとき**

**現在**
- 「新しい手法だ。とりあえず試してみよう」
- 「効果があるかは分からないが、話題だからやってみる」

**学習後**
- 「Agentic RAGは強化学習のMDP（マルコフ決定過程）として定式化できる。状態空間は検索結果の集合、行動空間は次のクエリ展開戦略、報酬関数は情報獲得量。これは情報理論的には適応的サンプリングの問題だ」
- 「従来のRAGと比較して、どのタイプのクエリ（特に多段階推論が必要な複雑なクエリ）で効果が期待できるか、理論的に予測できる」

**Graph RAGが出たとき**

**現在**
- 「グラフ構造を使うらしい。よく分からないが導入してみる」

**学習後**
- 「Graph RAGはドキュメント間の関係性を明示的にグラフとしてモデル化する。これはPageRankやランダムウォークといったグラフ理論の古典的アルゴリズムの応用。ベクトル検索は暗黙的な類似性しか捉えないが、グラフは明示的な関係性（引用、時系列、因果関係）を活用できる」
- 「特に文書間の構造が重要なドメイン（学術論文、法律文書、技術ドキュメント）で効果が高いと予測できる」

---

### 4.3 仕事での意思決定の質向上

**技術選択の場面**

**現在**
- 上司「リランカーを導入すべきか？」
- 自分「他社でも使われているので、試してみます」
- 上司「コストは？」
- 自分「...増えると思いますが、精度は上がると思います」

**学習後**
- 上司「リランカーを導入すべきか？」
- 自分「Cross-Encoderの理論的優位性から、特に複合クエリと長文クエリで効果が期待できます。小規模実験の結果、全体の20%のクエリに選択的に適用することで、コスト20%増、精度4%向上（統計的に有意、p=0.003）を達成できます。レイテンシは許容範囲内です。ROIは十分と判断します」

**評価フレームワーク設計の場面**

**現在**
- 「なんとなくNDCGを使っている」
- 「Claim-level Faithfulnessは重要そうだから測定している」

**学習後**
- 「NDCGは順位の重み付けを対数的に減衰させるため、上位の精度を重視する我々のユースケースに適している。数学的には、ユーザーの満足度が順位に対して対数関数的に減衰するという仮定に基づく」
- 「Claim-level Faithfulnessは、生成されたClaim単位での検証可能性を測定する。これは情報理論的には、生成内容と検索内容の相互情報量の代理指標と解釈できる」
